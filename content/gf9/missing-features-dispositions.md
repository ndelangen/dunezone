# GF9 missing-features dispositions

Companion to the [implementation specification](implementation-spec.md), checked against the body and seven existing comments of [DuneZone GF9 missing features](https://github.com/ndelangen/dunezone/issues/2353) on 20 October 2026. Historical delivery reports remain evidence of that delivery, not acceptance of the correction. Later resolved decisions control where old proposals disagree.

Package references name the owner roles in the implementation specification. Required correction and supporting tooling remain work to implement unless this table explicitly says otherwise.

## Later acceptance and release clarifications

Earlier demands to inspect actual-size prints or obtain human PDF approval are superseded by [the acceptance decision](https://github.com/ndelangen/dunezone/issues/2364#issuecomment-6293165287). Agents use focused existing export/render checks when code changes require them. The user reviews all four complete local web books. PDF creation remains with the existing publisher.

Earlier candidate-before-current wording is superseded by [the production-batch decision](https://github.com/ndelangen/dunezone/issues/2365#issuecomment-6293525914). Immediate normal publication, independent background readiness and forward correction are explicit.

Terminal faction-component and Edition-artifact recovery limits are documented operational limitations in the batch contract. They do not silently authorize a new administration or recovery platform. Diagnose actual failures and stop affected consumers when no supported normal action exists.

No required concern is unassigned after this classification. If implementation finds a new missing capability, update the existing issue with evidence, affected content and whether it is a bug, necessary supporting change or new product choice. Do not revive an old superseded proposal as if it were a requirement.
